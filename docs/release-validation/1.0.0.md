## 候補checkpointと確認状況

2026-10-25時点の採用PIX mainは `173da6d4916c1001976aa2e2fafbcfb2f83b0e0b`、Core pinは `154e9de7b813cee3cd9db07f22795a4a9e9ae833`。同日main CIの記録run `40168987430` と `40168987427` は成功している。これは通常main CI結果であり、7 targetのfinal 1.0.0 candidate archive/native matrixを意味しない。

現行CIには7 binaryを揃えたpre-release candidate artifactがない。現行 `release.yml` は手動実行で正式Releaseを作成・公開するため、未公開candidate用途で実行しない。従ってこのCI動線のままではfinal candidateの全archive実機matrixを行えない。1.0.0 matrixを実施した各OS/architectureのsource/Core、binary/artifact hash、機種、実command、物理操作、結果の記録は未提出であり、main CIの成功で埋めない。

現sourceの`src/dt295_capture.c`はmacOS以外のcapture入口をunsupportedとして返す。private `tools/finalize-private-release.py`はDT295 assetsを指定された場合も`darwin-arm64` archiveだけに追加する。これは現在の実装gateとpackage接続の状態であり、DT295を他OS/ABIの製品・回帰対象から除外する決定ではない。

## feature checks と結果

公開3コマンドは `pixd`、`pixctl`、`pix-ts`。PIXの内蔵カード状態は `pixctl card-status`、外部ATR/reset/APDUやPC/SC/WinSCardとは別機能である。1.0.0ではDT181/DT295のCARD status経路を製品固有手順に従って確認し、照会失敗時をunknownとして扱う。DT295の内部raw stateと物理カード在否の対応を未確認のまま補わない。stream中カード抜去/再挿入復帰は確認済み扱いにしない。

各実施行にはsource SHA、Core SHA、candidate run/artifact/archive SHA、native OS/architecture、機種、実command、物理操作、期待/実測、終了値とcleanupを記録する。final 1.0.0 candidateで未実施の行は理由とともに `未実施` / `未認定` とする。今回の文書変更ではsource・CI・実機検証を行っていない。
