# パケットストリームセッション互換ストレージ (dtv::capture)

本ドキュメントは、`dtv_userland_capture` ターゲット（ヘッダー: `include/dtv/userland/detail/packet_stream_session.h`、実装: `src/packet_stream_session.cpp`）が提供するパケットストリームセッションストレージ（D2 増分）の設計、スレッドモデル、および利用手順を解説する開発者向け文書である。

---

## 1. 概要と責務境界

`PacketStreamSession` は、各種 DTV 製品デーモンのデータプレーンで共有される、完全な TS パケット（188 バイト固定長）のリングバッファストレージ、読み取り、ドレイン、およびセッション終了状態管理を提供する内部互換コンポーネントである。

### 1.1 本コンポーネントが担当する範囲
- 188 バイト固定長の TS パケットのリングバッファキューイングとメモリ管理。
- 世代番号（`incarnation`）を用いた遅延リーダー（stale reader）の保護。
- アタッチ、デタッチ、およびシャットダウン時の一貫した状態遷移。
- バッファ満杯時の遅延コンシューマ（slow consumer）検知と終了フラグ設定。
- キューに残存するパケットのドレイン排出制御。

### 1.2 本コンポーネントが担当しない範囲 (製品側の責務)
- **スレッド・ワーカ・I/O 多重化**: 自らはバックグラウンドスレッドやワーカ、タイマーを所有しない。
- **ハードウェア制御**: USB バルク転送の起動・停止、エンドポイント制御は製品アダプタが担当する。
- **ストリーム解析**: パケット連続性カウンタ（CC）の監視、TEI（トランスポート誤り表示）フラグの検知、PID フィルタリングは製品アダプタがパケットを投入する前に実施する。
- **静止（Quiescence）とリソース返却**: 本ストレージにおけるセッション終了や終了状態の保持は、プロデューサコールバックの完全な静止（quiescence）や借用ファイルディスクリプタの返却保証、あるいは最終的な v1 ストリーム契約の完了を意味するものではない。物理的な停止やリソース解放の順序保証は製品側（例: `px4-userland` の `q3u4_stream.cpp` 等）が担保する。

---

## 2. スレッドモデルと排他制御

製品側のセッションクラス（例: `q3u4::Session` 等）は、本 `PacketStreamSession` を合成（メンバーとして保持）または派生して利用する。

- **単一ミューテックスの共有**: パケットの投入（`append_locked`）、リーダーの待機・読み出し（`begin_read_locked`, `read_wake_locked`, `finish_read_locked`）、およびデタッチ処理は、製品側が保持する単一の `std::mutex` および `std::condition_variable` を用いて同期する。
- **アトミックな状態観測**: パケット追加、終了状態の確定、および世代更新の判定が、製品側の状態観測と完全にアトミックに行われる。

---

## 3. セッション識別と世代管理 (Incarnation)

再利用されるセッションスロットにおいて、過去の接続を保持しているリーダーが、後から開始された新しいセッションのパケットやカウンタを誤読することを防ぐため、厳格な世代管理（`incarnation`）が導入されている。

### 3.1 アタッチの開始 (`begin_attach_locked`)
論理的なストリームアタッチが承認された時点で呼び出す。処理は以下の順序で厳密に実行される：
1. **状態検査**: 現在のセッションがアクティブまたはドレイン中（`attached || draining`）であれば、直ちに `Error::BUSY` を返す。
2. **世代上限検査**: 世代番号が上限（`incarnation == UINT64_MAX`）に達している場合、`Error::RESOURCE_LIMIT` を返す（世代は進めず、セッションのシャットダウンやクエリ・ドレインの利用可能性は維持される）。
3. **バッファ確保**: バッファ未確保（`packets == nullptr`）の場合のみ、`queue_packets * packet_size` の容量チェックを行い、`new (std::nothrow)` でメモリを確保する。確保失敗時は `Error::INTERNAL` を返す（世代は進めない）。すでにバッファが確保されている場合は再確保を行わず、既存の `capacity` を再利用する。
4. **状態初期化と Publication**: キューのポインタ（`head = 0`, `count = 0`）、状態フラグ（`attached = true`, `draining = false`）、カウンタ、および終了状態を初期化し、最後に **世代番号をインクリメント（`++incarnation`）** して publication を完了する。

### 3.2 起動失敗の補償 (`abandon_attach_locked`)
論理アタッチ後に製品側のハードウェア起動や USB エンドポイントの開始が失敗した場合に呼び出す。
- `attached = false`, `terminal = StreamTerminal::stopped`, `count = 0` を設定し、待機中のリーダーを起床させる。
- **すでに publication された世代番号は巻き戻さない**（古いリーダーが無効化された状態を維持するため）。

### 3.3 デタッチとドレイン (`detach_locked`)
ストリームセッションが停止された時点で呼び出す。
- 現在のアタッチ識別子（`Attachment`）と完全一致する場合のみ受理する（不一致時は `Error::NOT_FOUND`）。
- カウンタおよび終了状態をスナップショットとして固定し、セッションのアクティブフラグを解除する（`attached = false`）。
- すでにキューに蓄積されているパケットは破棄せず、リーダーがドレイン完了するまで読み取り可能として保持する（`draining = (count != 0)`）。
- 待機中のリーダーを起床させる。世代番号はこの時点では変更せず、次回のアタッチ時まで維持される。

### 3.4 シャットダウン時のデタッチ (`shutdown_detach_locked`)
デーモン全体の終了時に呼び出す。
- 終了状態をスナップショットとして記録し、キュー内の未読パケットを即座に破棄して待機中のリーダーを起床させる。

## 4. リーダー保護と 3 段階読み取りヘルパー

製品側が有界待機（timed wait）およびテスト Seam を所有できるよう、読み取り処理は 3 つのヘルパーに分割されている：

### 4.1 読み取りチケットの取得 (`begin_read_locked`)
リーダーが読み取り処理に入る際、最初に対象セッションのアタッチ識別子を検証して呼び出す。
- セッションがアクティブまたはドレイン中であれば、現在の世代番号を記録した `ReadTicket` を返す。
- 一致するセッションが存在しなければ `Error::NOT_FOUND` を返す。

### 4.2 待機述語 (`read_wake_locked`)
条件変数（`std::condition_variable`）による有界待機の起床述語として用いる。以下のいずれかが満たされたときに待機を終了する：
1. キューに読み取り可能なパケットが存在する（`count != 0`）。
2. セッションの終了状態が設定されている（`terminal != StreamTerminal::none`）。
3. チケットの世代番号と現在の世代番号が一致しなくなった（セッションが再利用された）。

### 4.3 読み出し完了とコピー (`finish_read_locked`)
待機から起床後、ロックを保持した状態で呼び出す。
- **世代不一致の遮断**: チケットに記録された世代番号と現在の世代番号が一致しない場合、パケットデータやカウンタ、ドレイン状態に一切アクセスすることなく、即座に `Result<StreamReadResult>::failure(Error::NOT_FOUND)` を返す。これにより、遅延したリーダーが新セッションのデータに触れることは構造的に排除される。
- **EOF 通知と終了判定**: 同一世代でキューが空（`count == 0`）であり、かつセッション終了状態が確定（`terminal != StreamTerminal::none`）している場合、失敗 Result ではなく成功値 `StreamReadResult{0U, true, false, final_terminal}` を返す（`eof == true`, `bytes == 0`, `timed_out == false`, `terminal` に確定した終了事由。同時に `draining = false` となり待機スレッドへ通知される）。空キューで終了状態が未確定の場合はタイムアウト成功値 `{0U, false, true, StreamTerminal::none}` を返す。共通ライブラリの `Error` enum に `END_OF_FILE` は存在せず、ストリーム終端は失敗エラーではなく戻り値構造体の `eof` フィールドによって通知される。
- **データ返却**: 有効なパケットが存在する場合、リングバッファの折り返し（2 スパン）を考慮して呼び出し元の出力バッファ（`output`）へコピーし、消費したパケット数およびバイト数を更新して返却する。

## 5. パケット投入とバックプレッシャ (`append_locked`)

製品側の USB 受信コールバックから、1 パケット（188 バイト）単位で投入する。

```cpp
void append_locked(ByteView packet) noexcept;
```

- **入力前提条件**: 本関数は内部 locked helper であり、`packet.size` や `packet.data` の検証は行わない。呼び出し元は、`packet.data` が 188 バイト以上の有効なバッファを指していることを保証する責務を負う。
- **通常投入**: キューに空きがある場合、`counters.packets` と `counters.bytes` を加算し、末尾位置へ 188 バイトを直接 `std::memcpy` して `count` をインクリメントし、待機中のリーダーを起床させる。
- **バッファ満杯時**: キューが満杯（`count == capacity`）の場合、`counters.queue_drops` を加算し、終了状態へ `StreamTerminal::slow_consumer` を代入して条件変数を通知（`notify_all`）する。満杯時のパケット破棄の抑止や投入停止制御は製品側アダプタが担当する。

---

## 6. ビルドと依存関係

本コンポーネントは、CMake オプション `DTV_USERLAND_BUILD_CAPTURE=ON` を指定したときのみビルドされる。

```cmake
# キャプチャコンポーネントの有効化
option(DTV_USERLAND_BUILD_CAPTURE "Build the internal packet-session storage" ON)
```

- **依存ターゲット**: `dtv::core` および `Threads::Threads`。
- **レシーバからの独立性**: `dtv::receiver` には依存しない。そのため、受信機互換エンジンを含めずにパケットストレージのみを利用する capture-only インストールおよびリンクが可能である。
